# ตัดเกมออก เหลือแอปรายรับรายจ่ายที่ใช้ง่ายที่สุด

วันที่ 2026-11-12 · สถานะ: รออนุมัติ

## ทำไมต้องทำ

เจ้าของแอปสร้างฝั่งเกม RPG ขึ้นมาเพื่อกระตุ้นให้ตัวเองจดรายรับรายจ่าย ใช้จริงมาระยะหนึ่งแล้วสรุปว่า
**เกมไม่ได้ดึงดูดอีกต่อไป** สิ่งที่ทำให้กลับมาเปิดแอปจริงๆ คือ "ใช้งานง่าย ไม่ต้องกดเยอะ" กับตัวเลขสรุป
ไม่ใช่ EXP ทอง หรือมอนสเตอร์

คำพูดของเจ้าของ: *"ฝั่งเกมส์อาจจะไม่ดึงดูดใจฉันแล้ว สิ่งที่ดึงดูดจริงๆคือการใช้งานที่ง่าย ไม่ต้องกดเยอะ
รายการสรุปรายวันรายสัปดาห์หรือรายเดือน หรือเทียบต่อเดือนทั้งปี นั่นแหละที่สนใจจริงๆ
กับการสรุปรายจ่ายก่อนไหนมากสุดน้อยสุด เหลือใช้ได้จริงวันละเท่าไหร่"*

ตอนถามว่าจะรื้อเกมทิ้งทั้งหมด (รวมฝั่งลงทุน/ราคาสด) หรือซ่อนไว้หลังปุ่ม เจ้าของเลือก **รื้อทิ้งทั้งหมด**
และเมื่อถามต่อว่าหน้าตาแบบพิกเซล retro จะเอาไว้มั้ย เจ้าของเลือก **เปลี่ยนเป็นเรียบๆ**

## วิธีใช้งานจริงของเจ้าของ

เขาใช้แอปเป็นสองจังหวะ เข้าใจจังหวะนี้แล้วจะเข้าใจว่าทำไมสเปกถึงเป็นแบบนี้

**ต้นเดือน (เดือนละครั้ง)** — เงินเดือนเข้าวันทำการสุดท้ายของเดือน แล้วเขาจะ
1. กดบันทึกเงินเดือนเข้าเป็นรายรับ
2. กด "ยกแผนจากเดือนที่แล้ว" เพื่อดึงรายจ่ายประจำมา
3. แก้ยอดบางรายการที่เปลี่ยนไป
4. ไล่จ่ายตามลิสต์
5. **จ่ายเสร็จแต่ละตัวต้องมาพิมพ์บันทึกเป็นรายจ่ายอีกรอบ** ← จุดที่เสียเวลาที่สุด

ข้อ 5 คือการกรอกข้อมูลเดียวกันสองที่ ทั้งที่ยอดอยู่ในแผนอยู่แล้ว และแอปก็ไม่รู้ว่าแถวไหนจ่ายไปแล้ว
เจ้าของต้องจำเอง

**ระหว่างเดือน (ทุกวัน)** — จดรายจ่ายย่อย ปัญหาคือ**วันที่ของรายการถูกล็อกเป็นวันนี้เสมอ แก้ไม่ได้**
เวลาจดย้อนหลังยอดเลยไปลงผิดวัน ทำให้ตัวเลขสรุปไม่ตรงกับความเป็นจริง

## เป้าหมาย

1. ตัดฝั่งเกมและฝั่งลงทุนออกทั้งหมด เหลือแอปรายรับรายจ่าย 3 หน้า
2. **ระบุวันที่ของรายการได้เอง** ทั้งตอนจดใหม่และตอนแก้รายการเดิม
3. **เปลี่ยนหน้าตาจากพิกเซล retro เป็นแบบเรียบ** ตัวหนังสืออ่านง่าย พื้นสะอาด เน้นตัวเลข
4. **ปุ่ม "จ่ายแล้ว" ในหน้าแผน** กดครั้งเดียวบันทึกเป็นรายจ่ายให้ และจำว่าแถวนี้จ่ายแล้ว
5. **หน้าสรุปหน้าเดียว** ที่ตอบ 4 คำถามโดยไม่ต้องกดสลับอะไรเลย
   - วันนี้เหลือใช้ได้จริงเท่าไหร่
   - สัปดาห์นี้ใช้ไปเท่าไหร่ วันไหนหนักสุด
   - เดือนนี้หมวดไหนกินเยอะสุด น้อยสุด
   - 12 เดือนทั้งปีเทียบกันในภาพเดียว

## สิ่งที่ไม่ทำ (non-goals)

- ไม่แตะโปรโตคอลที่คุยกับ Google Sheet ชีตเดิมและ TOKEN เดิมต้องใช้ต่อได้ทันที ไม่ต้องย้ายข้อมูล
- ไม่ตัดอะไรออกจากหน้าแผน — ถามแล้ว เจ้าของตอบว่า **"ไม่ต้องตัด"** ทั้ง 7 อย่าง
  (รายรับ · รายจ่ายประจำ · หนี้/ผ่อน · ถังออม % + เป้า · สรุปแยกตามบัญชี · เครื่องคิดค่าน้ำมัน · ยกแผนเดือนก่อน)

- ไม่เปลี่ยนชื่อ repo และไม่เปลี่ยน base path ของ GitHub Pages (`/IRPG-INCOME-GAME/`)

## สิ่งที่ถือว่าล้มเหลว (anti-goals)

- **ข้อมูลเก่าหาย** ไม่ว่าจะในเครื่องหรือในชีต — เป็นความล้มเหลวที่ร้ายแรงที่สุด
  ข้อมูลรายรับรายจ่ายสะสมมา 13 เดือนตั้งแต่สมัยโปรเจค 2
- หน้าสรุปกลับไปมีโหมดซ่อนอยู่ จนต้องจำว่าตอนนี้อยู่โหมดไหน
- ตัดเกมออกแล้วแต่ยังเหลือเศษ UI ของเกมค้างอยู่ตามหน้าต่างๆ
- "ง่ายขึ้น" แปลว่ากดน้อยลง ไม่ใช่เห็นข้อมูลน้อยลง

## โครงใหม่ — 3 หน้า

แถบล่างเหลือ 3 ช่อง: **บันทึก · แผน · สรุป** ส่วน **ตั้งค่า** อยู่หลังปุ่ม ⚙ บนหัวเรื่อง (ทำไว้แล้ว)
ไม่มีหน้า "ที่พักของฮีโร่" ไม่มีประตูเข้าโลก ไม่มีแถบ EXP/ทองบนหัวเรื่อง เปิดแอปมาเจอหน้าบันทึกเลย

### หน้าบันทึก

สิ่งที่ทำทุกวัน อยู่บนสุดเสมอ

- ช่องจดด่วนแบบเดิม (`กาแฟ 120` / `+เงินเดือน 45000` / `ค่าไฟ 100*3`) เดาซองให้เองและจำซองที่เคยเลือก
- **ใหม่: ช่องวันที่ข้างช่องจดด่วน** ค่าเริ่มต้นเป็นวันนี้ เปลี่ยนได้ก่อนกดเพิ่ม
  และเปลี่ยนแล้วค้างไว้จนกว่าจะเปลี่ยนใหม่หรือปิดแอป เพราะเวลาลงย้อนหลังมักลงหลายรายการของวันเดียวกันรวด
- **ใหม่: แก้วันที่ของรายการที่จดไปแล้วได้** จากในแถวรายการ
- ตัวเลข "วันนี้เหลือใช้ได้" อยู่ใต้ช่องจด
- ปฏิทินของเดือน (วันหยุด เหตุการณ์ วันเงินเดือน) — เก็บไว้ เพราะใช้ดูว่าวันไหนจ่ายอะไร
- รายการแยกตามวัน แก้ยอด แก้ซอง แก้วันที่ ลบได้ · ลบแล้วเอากลับคืนได้ (ทำไว้แล้ว)

### หน้าแผน

เนื้อหาเดิมครบทั้ง 7 อย่าง ไม่ตัด เพิ่มอย่างเดียว

- **ใหม่: ปุ่ม "จ่ายแล้ว" ทุกแถวในรายจ่ายประจำและหนี้/ผ่อน**
  กดแล้วแอปสร้างรายการจ่ายให้เอง ใช้ชื่อแถวเป็นโน้ต ใช้ยอดในแถวเป็นจำนวน ใช้ซองชื่อเดียวกับแถว
  วันที่ = วันที่เลือกไว้ในหน้าบันทึก (ค่าเริ่มต้นคือวันนี้)
- แถวที่จ่ายแล้วขึ้นเครื่องหมายชัดเจนและจางลง · กดซ้ำเพื่อยกเลิกได้ (ลบรายการที่เพิ่งสร้าง)
- หัวหน้าแผนบอกภาพรวม เช่น "จ่ายแล้ว 5 จาก 9 รายการ · เหลือต้องจ่ายอีก 12,400"
- สถานะจ่ายแล้วต้องคำนวณจากรายการที่จดไว้จริง ไม่ใช่เก็บเป็นธงแยก มิฉะนั้นลบรายการทิ้งแล้วสถานะจะเพี้ยน

### หน้าสรุป — หน้าเดียว เลื่อนลงอ่าน

เจ้าของเลือกแบบนี้จากแบบจำลองสองแบบ **ห้ามมีปุ่มสลับโหมด** เรียงจากใกล้ตัวที่สุดลงไปไกลที่สุด

1. **วันนี้เหลือใช้ได้** — ตัวเลขใหญ่สุดของหน้า พร้อมยอดคงเหลือทั้งเดือนและจำนวนวันที่เหลือ
2. **สัปดาห์นี้** — แท่ง 7 วัน จันทร์ถึงอาทิตย์ · ยอดรวมของสัปดาห์ · วันที่หนักสุด · เฉลี่ยต่อวัน
3. **เดือนนี้** — ยอดที่ใช้เทียบแผน · หมวดเรียงจากมากไปน้อยพร้อมแท่ง · บอกชัดว่าหมวดไหนมากสุดน้อยสุด
4. **ทั้งปี** — 12 แท่งเทียบกัน เดือนปัจจุบันเน้นสี เดือนที่ยังไม่ถึงเป็นแท่งจาง
   แตะแท่งไหนแล้วเด้งไปดูเดือนนั้น

ตัวเลือกเดือนบนหัวเรื่องยังอยู่ เปลี่ยนเดือนแล้วทุกส่วนเปลี่ยนตาม (ส่วน "วันนี้" แสดงเฉพาะเดือนปัจจุบัน)
หนี้/ผ่อน และถังออมย้ายไปอยู่หน้าแผนอย่างเดียว ไม่ต้องโชว์ซ้ำในหน้าสรุป

## หน้าตาใหม่ — เรียบ

ทิ้งภาษาภาพพิกเซลทั้งหมด: `bevel` `sunken` `track` `pixel` `font-rpg` สีชุด `retro-*` สไปรต์
กรอบนูนและเงาแข็ง ไปเป็นหน้าตาเรียบที่เน้นให้อ่านตัวเลขง่าย

- พื้นสะอาด การ์ดแยกด้วยพื้นหลังต่างระดับหรือเส้นบาง ไม่ใช่กรอบนูน
- ตัวเลขเงินใช้ฟอนต์ความกว้างคงที่ ตัวเลขหลักของหน้าตัวใหญ่ชัด
- สีใช้บอกสถานะเท่านั้น (ยังไม่เกินงบ / ใกล้เต็ม / เกิน) ไม่ใช่ใช้ตกแต่ง
  และสถานะต้องมีข้อความกำกับด้วยเสมอ ไม่พึ่งสีอย่างเดียว
- คอนทราสต์ตัวอักษรต่อพื้นอย่างน้อย 4.5:1 ทั้งโหมดมืดและสว่าง
- โหมดมืด/สว่างยังอยู่ และตอนเปิดแอปต้องไม่แฟลชขาวก่อนสลับเป็นมืด

> งานนี้แตะเกือบทุกไฟล์ที่เหลือ คนทำควรทำทีหลังการลบ เพื่อจะได้ไม่ต้องจัดหน้าตาให้ของที่กำลังจะหายไป

## กติกาของเลขและสถานะ

ส่วนนี้มาจากการตรวจสเปกรอบหนึ่ง ข้อ 1 กับ 2 เจ้าของเป็นคนเลือก ที่เหลือเป็นการตัดสินใจของผู้เขียนสเปก

### 1. "วันนี้เหลือใช้ได้จริง" — เจ้าของเลือก

```
(รายรับ − รายจ่ายประจำทั้งก้อน − รายจ่ายย่อยที่ใช้ไปแล้ว) ÷ จำนวนวันที่เหลือในเดือน
```

กันรายจ่ายประจำออกตั้งแต่ต้นเดือน **ไม่สนว่าจ่ายบิลไปแล้วหรือยัง** ตัวเลขจะได้นิ่งทั้งเดือน
ไม่กระตุกตอนไล่จ่ายบิล · "รายจ่ายย่อย" คือรายการที่จ่ายออกซึ่ง **ไม่ใช่** รายการที่ทำให้แถวในแผน
ขึ้นว่าจ่ายแล้ว (นิยามในข้อ 2) มิฉะนั้นบิลจะถูกหักสองรอบ

- "รายรับ" ใช้ยอดรวมของแถวรายรับในหน้าแผนของเดือนนั้น ถ้าเดือนนั้นไม่มีแถวรายรับเลย
  ให้ใช้ยอดรวมของรายการประเภทรับที่จดไว้จริงแทน *(การตัดสินใจของผู้เขียนสเปก — ประวัติ 13 เดือน
  ที่ยกมาจากโปรเจค 2 ไม่ได้จดเงินเดือนไว้ทุกเดือน ถ้าใช้รายการที่จดอย่างเดียวเดือนเก่าจะเพี้ยน)*
- ถ้าติดลบ ให้แสดงว่าใช้เกินไปเท่าไหร่ ไม่ใช่โชว์เลขติดลบหารวัน
- ฟังก์ชันเดียวกันนี้ใช้ทั้งใต้ช่องจดด่วนและหัวหน้าสรุป ต้องไม่มีสองสูตร

### 2. แถวในแผนขึ้นว่า "จ่ายแล้ว" เมื่อไหร่ — เจ้าของเลือก

**เมื่อเดือนนั้นมีรายการจ่ายที่โน้ตตรงกับชื่อแถว** ปุ่มจ่ายแล้วเขียนโน้ตเป็นชื่อแถวพอดี
รายการที่พิมพ์เองก็เลยนับด้วย และของเก่า 13 เดือนขึ้นย้อนหลังเองโดยไม่ต้องแปลงข้อมูล

รายละเอียดที่เหลือเป็น*การตัดสินใจของผู้เขียนสเปก*:
- เทียบชื่อแบบตัดช่องว่างหัวท้ายและไม่สนตัวพิมพ์เล็กใหญ่ · **ไม่ดูยอดเงิน** จ่ายมากน้อยกว่าแถวก็ถือว่าจ่ายแล้ว
- แถวที่ยังไม่ได้ตั้งชื่อ ไม่มีปุ่มจ่ายแล้วและไม่นับในตัวเลข "จ่ายแล้ว x จาก y"
- ชื่อซ้ำกันสองแถว ให้ถือว่าจ่ายแล้วทั้งคู่เมื่อมีรายการชื่อนั้น — เป็นกรณีที่เจ้าของตั้งชื่อกำกวมเอง
  ไม่คุ้มที่จะเขียนโค้ดรองรับ
- เปลี่ยนชื่อแถวหลังจ่ายแล้ว สถานะจะกลับเป็นยังไม่จ่าย — ยอมรับได้ ดีกว่าเก็บธงแยกแล้วเพี้ยนตอนลบรายการ
- "กดซ้ำเพื่อยกเลิก" ลบรายการที่ตรงชื่อซึ่งจดล่าสุดของเดือนนั้นหนึ่งรายการ และต้องย้อนคืนได้
  ด้วยแถบ "เอากลับคืน" เหมือนการลบรายการปกติ

### 3. วันที่กับเดือนที่เลือกขัดกัน ให้วันที่ชนะ

*(การตัดสินใจของผู้เขียนสเปก)* ทั้งการจดด่วนและปุ่มจ่ายแล้ว ใช้วันที่ในช่องวันที่เสมอ
และถ้าวันที่นั้นอยู่คนละเดือนกับที่กำลังดูอยู่ **ให้หน้าจอเปลี่ยนไปเดือนนั้นตาม**
จะได้เห็นรายการที่เพิ่งจดทันที ไม่ใช่จดแล้วหาย ทิ้งพฤติกรรมเดิมของ `dateInMonth(cur)` ไป

### 4. ส่วน "สัปดาห์นี้" แสดงเฉพาะเดือนปัจจุบัน

*(การตัดสินใจของผู้เขียนสเปก)* เดือนหนึ่งมี 4-5 สัปดาห์ ถ้าเลือกดูเดือนย้อนหลังแล้วต้องเลือกอีกว่า
สัปดาห์ไหน ก็กลับไปมีโหมดซ่อนอีก — ซึ่งเป็นสิ่งที่สเปกนี้ตั้งใจกำจัด
เลือกเดือนย้อนหลังเมื่อไหร่ ส่วน "วันนี้" กับ "สัปดาห์นี้" หายไปทั้งคู่ เหลือส่วนเดือนกับส่วนปี

### 5. ปฏิทินในหน้าบันทึก เก็บไว้ แต่สีเหลือความหมายเดียว

*(การตัดสินใจของผู้เขียนสเปก)* ตอนนี้ช่องวันในปฏิทินถูกระบายสีด้วย `dayLog` กับ `validRest`
ซึ่งอยู่ในรายการที่ต้องลบ ให้เขียนฟังก์ชันเล็กๆ ขึ้นมาใหม่แทน คืนยอดจ่ายรวมของแต่ละวัน
แล้วระบายแค่ "วันนั้นใช้เกินงบรายวันหรือไม่" พร้อมตัวเลขกำกับในช่อง ไม่พึ่งสีอย่างเดียว
ฟีเจอร์ "วันนี้ไม่ได้ใช้เงิน" (`rest`) หายไปทั้งหมดตามที่ตกลงไว้ ส่วนคีย์ `investor-rpg:money.rest`
ในเครื่องปล่อยทิ้งไว้ ไม่ต้องลบ

### 6. ปุ่มจ่ายแล้วบนแถวหนี้/ผ่อน ห้ามเดินเลขงวด

*(การตัดสินใจของผู้เขียนสเปก)* `carryMonth()` เดินเลขงวด `n` ให้อยู่แล้วตอนยกแผนข้ามเดือน
ถ้าปุ่มเดินให้อีก งวดจะนับซ้ำและ `payoffMonth()` จะบอกเดือนผ่อนหมดผิด แล้วค่าผิดนั้นถูกเขียนลงชีต
ปุ่มนี้สร้างรายการจ่ายอย่างเดียว ไม่แตะ `n` `of` `total`

## ข้อจำกัดทางเทคนิค

- React 19 · TypeScript · Vite · Tailwind v4 — ของเดิม ไม่เพิ่มอะไร
- คีย์ localStorage ทั้งหมดยังขึ้นต้นด้วย `investor-rpg:` **ห้ามเปลี่ยน** ไม่งั้นข้อมูลในเครื่องหายหมด
  คีย์ของเกม (`investor-rpg:game` ฯลฯ) ไม่ต้องลบทิ้ง ปล่อยไว้เฉยๆ เผื่อเจ้าของเปลี่ยนใจ
- รูปแบบข้อมูลในชีตคงเดิมทุกคอลัมน์ · เดือนเก็บเป็นข้อความ `yyyy-MM` ไม่ใช่วันที่
  (เคยพังมาแล้วเพราะ Google Sheet แปลงเป็น Date เอง)
- ทำงานออฟไลน์ได้ แก้แล้วส่งขึ้นชีตหลังหยุดพิมพ์ 1.5 วินาที · ดึงลงตอนเปิดแอปและตอนกลับมาหน้าจอ
- รองรับไทย/อังกฤษ และโหมดมืด/สว่าง เหมือนเดิม
- `npm run check` ต้องผ่าน · `npm run build` ต้องผ่าน · ไม่มี error ใน console
- ปุ่มทุกปุ่มต้องกดได้ด้วยนิ้ว ไม่เล็กกว่า 24px ตามขั้นต่ำ WCAG 2.2 AA · ตัวที่กดทุกวันควรถึง 44px
- ต้องทดสอบที่กว้าง 375px เป็นหลัก เพราะใช้บนมือถือ

## ที่ปล่อยให้คนทำตัดสินใจเอง

- โครงไฟล์หลังลบเกม — จะยุบ `src/money/` ขึ้นมาเป็น `src/` เลยหรือคงไว้ก็ได้
- จะวาดแท่ง 7 วันและ 12 เดือนด้วยคอมโพเนนต์เดียวกันหรือแยกกัน

- ลำดับการลงมือ แต่แนะนำให้ลบเกมก่อนแล้วค่อยเพิ่มของใหม่ จะได้เห็นว่าอะไรพังตั้งแต่ตอนลบ
